# Section 5 review: optional LangChain migration guidance

Section 5 is implemented and verified. Open **http://127.0.0.1:8010/**, save a comparison, select a supported finding, and scroll down in the evidence inspector to **AI migration guidance**. Confirm evidence sharing and click **Explain finding**. No provider request is made merely by uploading, comparing, selecting, reopening, or refreshing status.

## Free provider and credentials

The selected adapter is LangChain ChatGroq, using `openai/gpt-oss-120b` hosted by Groq. This does not use an OpenAI API key, paid subscription, local model, or automatic provider fallback. The user's project key is stored outside the checkout and OneDrive in the existing private runtime folder. It is not embedded in browser assets, configuration examples, screenshots, logs, or reports.

As checked on November 8, 2026, Groq lists this model on its Free plan with 30 requests/minute, 1,000 requests/day, 8,000 tokens/minute, and 200,000 tokens/day. Exact account limits can differ. The Free plan is separate from the paid Developer upgrade, which requires a payment method. Stay on Free and do not add billing for this project. The application cannot verify an account's plan or guarantee that terms remain unchanged. Sources: [official rate limits](https://console.groq.com/docs/rate-limits), [billing FAQs](https://console.groq.com/docs/billing-faqs).

Run `scripts/configure-ai.py` in an interactive terminal to enter/replace the key at a hidden prompt. It requires an initialized project runtime, asks the operator to confirm Free-plan eligibility, and saves plaintext bytes in `groq.key` for server use. Runtime setup restricts its directory to the current Windows account; this is access control, not encryption. The script refuses noninteractive input to avoid accidental echo. Key changes take effect without restart. `API_AUDITOR_AI_ENABLED=false` disables generation after backend restart.

On explicit request, selected endpoint/field names, pointers, policy context, and bounded contract values leave the laptop for Groq. Original documents, titles, descriptions, examples, defaults, vendor extensions, and arbitrary object bodies are excluded. Some legitimate evidence values, such as enum strings, can still contain private data or instructions; they remain untrusted input. Groq describes default non-retention of inference data with reliability/abuse exceptions, always-retained usage metadata, and account data controls. Review [its data policy](https://console.groq.com/docs/your-data) before sharing private contracts.

## Implementation and boundaries

The pipeline is a LangChain `ChatPromptTemplate` composed with `ChatGroq.with_structured_output`, followed by strict Pydantic validation and binding checks. Native JSON-schema output is requested, but provider errors and invalid responses are still handled locally. These interfaces are documented in [LangChain's Groq integration](https://docs.langchain.com/oss/python/integrations/chat/groq) and [Groq structured output](https://console.groq.com/docs/structured-outputs).

Only a saved comparison and one supported finding ID are accepted. The browser cannot submit replacement evidence, choose a paid model, change provider URLs, or override policy. The server reloads its immutable snapshot and constructs a minimized context, capped at 10,000 UTF-8 bytes. Before/after values are represented as exact JSON text, capped at 1,600 characters each; omitted values are labelled. Large integer digits are preserved.

Each request assigns the selected finding the short alias `F1` inside its isolated model context. The model must return exactly that alias and a nonempty, unique subset of the supplied `before`/`after` reference keys. After validation, the server maps `F1` back to the actual requested finding ID. This avoids unreliable copying of opaque hash characters while preventing invented finding associations. Pointer values and authoritative severity always come from the server snapshot, never the model.

Accepted output contains an explanation, bounded migration and verification steps, caveats, and evidence references. Extra properties, severity overrides, unknown aliases/references, missing/blank text, oversized fields/lists, incomplete generation, and malformed JSON are rejected. Schema validation does not detect every unsupported factual claim. The model has no executable tools, retrieval, URL fetching, patch execution, or client source access. LangSmith tracing is explicitly disabled around calls.

The provider adapter fixes the HTTPS Groq endpoint, ignores ambient HTTP proxies, refuses redirects, caps response bodies at 64 KiB, and requests at most 1,600 output tokens. There is one provider attempt per request, no SDK/application retries, a 20-second transport timeout, and a 25-second overall deadline. Invalid credentials, provider/schema failures, quota exhaustion, and timeouts become bounded, redacted errors. Provider bodies and exception text are not returned to the browser. Quota errors activate a 60-second local cooldown. One request may run at a time; additional requests receive 429 rather than joining an unbounded queue.

Development guards permit four attempts/minute and a configurable 50/day per process by default (maximum configurable daily limit 100). Failed attempts count. Counters use UTC and reset on process restart; they are not durable account-wide quotas or billing controls. Cached results make no provider request and consume no attempt budget. Groq may enforce stricter quotas.

AI output never edits the comparison snapshot, deterministic severity, coverage warnings, or JSON/Markdown exports. Explanations are separately labelled advisory text. They are cached in process memory for up to one hour with at most 100 entries. Keys include snapshot/input hashes, finding, engine/policy, provider/requested model, prompt text hash, and prompt version. Responses retain reported model/fingerprint, generation time, usage, attempt count, and latency. Model aliases can change upstream; a cached response preserves the identity reported when generated, without claiming to detect upstream revisions during its TTL.

Deleting a comparison evicts its cache entries. The server rechecks snapshot existence after inference, so a record deleted during generation is not cached again. Restart clears the cache. There is no database migration or new persistent AI table. AI exports and persistence across restarts are outside this section.

## Browser behavior

The evidence inspector shows missing-key, disabled, unavailable, supported/unsupported, loading, success, and failure states. Unsaved comparisons explain that saving is required for AI. A per-finding checkbox confirms evidence sharing before the generate button enables. Duplicate clicks are guarded. Switching findings or reports discards stale responses and resets consent. Guidance renders as escaped React text; model strings are never executed as HTML/Markdown. Mobile Evidence tabs display the same feature. AI failures leave findings and exports available.

Source and dependency changes remain within Apiproj. The 22 new Python wheel artifacts were resolved from official PyPI, installed with SHA-256 checking, and recorded in [download provenance](section-5-downloads.json). The full lock now has 66 packages; [the previous 44-package lock](section-3-requirements.lock.txt) is preserved. No npm dependency changed, browser/model downloaded, hosting created, or GitHub repository published.
